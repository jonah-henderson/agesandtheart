# The walk checklist: everything built headlessly that still wants a pair of eyes, in priority order.
#
# NOT a drive-server script. `scripts/drive-server.sh` writes to a throwaway world, so an Age it creates is
# not one you can walk. Paste these into a **client** chat (`./gradlew :fabric:runClient`).
#
# What each is FOR is written above it, and each says WHAT A WALK HAS TO SETTLE — that sentence is the
# acceptance test, not "does it look all right". Every line is deliberately seeded so what you see is what
# the next person sees; `/age list` prints a seed and a recipe, and pasting a printed composition back into
# `/age compose` rebuilds it exactly.
#
# **EVERY COMMAND BELOW WAS DRIVEN AGAINST A REAL SERVER ON 2026-09-05 AND CREATES THE AGE IT CLAIMS TO.**
# Keep it that way. The last list rotted partly because it accumulated plausible-looking lines nobody had
# run — `climate.temperature=frigid` (that slot takes a numeric range), `phenomena=blizzard` (silently
# dropped; the key is `phenomena.happens=`), `two suns` (not a word). A line that errors in chat is worse
# than no line, because it reads as the feature being broken.
#
# **DELETE AN ENTRY WHEN IT HAS BEEN WALKED.** Started over 2026-09-05 because the last one was not kept
# that way: it grew verdicts on things since rebuilt, open items settled elsewhere and never struck out,
# and two lettered sequences running at once. A verdict that outlives its code is worse than no note. When
# a walk settles something the finding goes to `notes/decisions.md` in two lines and the entry goes here.
#
# The old file is in git at `f8325b7:scripts/checks/visual-backlog.txt`. Everything live in it was already
# recorded in `notes/decisions.md` or `notes/the-art-implementation-plan.md`; what was still unwalked is
# items 6 to 8 below.

# ══ 1. THE REWARD LOOP ═══════════════════ WALKED AND GOOD 2026-09-05; CALIBRATION STILL OPEN ══
# The phase's headline, and the reason the danger pole went first: **write a dangerous Age, read what it
# will hold before you bind the book, go there and find it.** The loop works end to end. What is left is
# the one number it exists to settle.
#
# You need a desk with a geologist's tools in the room. The tools are a toolbox (shaped: plank/slab/plank
# along the bottom, sticks up the middle) filled shapeless with a brush, a rime crystal, a lodestone, a
# diamond, a barrel and a deretheni plate. The rime crystal is the awkward one — it comes from item 5, so
# either walk that first or `/give` yourself one.
#
# THE SENTENCE IS TWO PAGES — `infernal` and `age` — which is what makes this practical at a desk.
/age write hellish 11 infernal age
/age danger score hellish
/age tp hellish
#
# MEASURED 2026-09-05, so the walk has something to disagree with:
#   danger 0.430 (made of 1.000, lives in 0.000, happens 0.000, dark 0.800) — pays out, no ruins.
#   That is three veins a chunk, which the survey should word as **"a little"**.
#
# WALKED 2026-09-05 (Jonah): "everything worked as intended". The survey reads, it fits, and it reports
# amounts rather than forecasts. Those sub-questions are settled and struck.
#
# WHAT IS LEFT IS THE CALIBRATION, and this walk is the only instrument for it. `pays_above` is a
# placeholder `0.25` in `art/danger.json`.
#
# **JONAH'S ANCHOR (2026-09-05): a straight duplicate of the nether — `infernal age`, one page costing 3
# ink — should JUST BARELY not qualify.** It scores 0.430, so the line goes just above that.
#
# Measured 2026-09-05, seed 11, the neighbourhood either side:
#     0.080  a roof and nothing else
#     0.180  age ghast spawns
#     0.300  age inferno phenomena   /   age warden spawns
#     0.350  a lava sea alone
#     0.430  age infernal            <-- the anchor: must not pay
#     0.475  lava + roof + monsters
#     0.500  lava + inferno
#     0.580  lava + roof + inferno
#     0.720  age teeming ghast spawns
#
# The gap is 0.430 -> 0.475, so the line is somewhere in it. **0.45 sits dead centre** and gives a rule
# worth stating: one template word never pays; the template plus one deliberate hazard does.
#
# TWO THINGS TO DECIDE WITH IT, because both follow from the same number:
#   - `allowsRuins` is this threshold read backwards. Moving it to 0.45 flips lava-only, inferno-only,
#     warden Ages and the nether copy itself from "too dangerous for ruins" into "may hold a city".
#   - **It makes "a trace" unreachable.** The lowest paying score would be 0.45, which is three veins and
#     already the LITTLE band. Design §7.7 names *a trace* as the bottom of the vocabulary, so the bands
#     want rebasing on whatever the threshold becomes (TRACE 3-4, LITTLE 5-6, SOME 7-9, MUCH 10-19,
#     IMMENSE 20+ for a threshold of 0.45).
#
# STILL WORTH WALKING: does finding ~4 ore in a chunk's band feel like the trip was worth making?

# Checked only as arithmetic (`ProtectiveSuitCheck`) and as a datapack that loads. The armour-stand probe
# was abandoned: a playerless server does not keep one selectable. Item 1's `hellish` is the fire half;
# this is the cold half, and it is the same Age item 5 wants.
#
/age write frozen 4242 age blizzard phenomena frozen climate
/age tp frozen
#
# WHAT A WALK HAS TO SETTLE:
#   - Four pieces really do stop you catching fire in an inferno (`/age tp hellish`).
#   - Powder snow and a frozen Age do nothing to you.
#   - A full set survives a swim in lava and a PARTIAL set does not.

#     contact-scoped effect could plausibly get wrong — a blaze should still be a fight.
#   - The trade is felt: it is armour you wear INSTEAD of armour, so a fight should go worse in it.

# ══ 3. THE TOOLBOX HAS NEVER BEEN OPENED OR CARRIED ══════════════════════════ Built 2026-09-05 ══
# Two halves, neither reachable from a headless server, and the first is the one that matters.
#
#   - THE FENCE. It must take only things that carry durability, or twenty-seven slots is a shulker box
#     for four sticks. Cannot be checked offline AT ALL: `Bootstrap.bootStrap()` does not bind item
#     components, so no `ItemStack` can be built in a spec ("Components not bound yet"). Try to put dirt
#     in one.
#   - THE REFILL. Carry a toolbox holding a spare, break the tool in your hand, and the spare should
#     arrive in that hand. **ARMOUR TOO**, which is the less usual half — break a boot and the spare boot
#     should go on. Besides that it fires: that it takes from the right compartment, that the contents
#     survive the box being broken and replaced, and that the client does not flicker when a refused item
#     is dragged in (the menu carries its own type precisely so that it should not).

# WHAT A WALK HAS TO SETTLE:
#   - **Whether that is right.** "Absurd amounts" is what was asked for, and it may be exactly right for a
#     world you raid once — or the x10 may want pulling back. This is a judgement, not a measurement.

#   - That racing them is FUN rather than merely fatal.

# ══ 5. THE RIME CRYSTALS AND THE SKATES HAVE NEVER BEEN SEEN OR WORN ═════════ Built 2026-09-05 ══

# every climate cold enough that nothing thaws, AND a blizzard.

#
# WHAT A WALK HAS TO SETTLE:
#   - That a crystal on a cliff face reads as a FIND rather than as noise.
#   - That the blue tint over vanilla's amethyst is legible at distance. It is a placeholder either way
#     (Phase 9), so the question is only whether it carries until then.
#   - That climbing to them is the scaffolding problem it was meant to be — more the higher you go.
#   - **THAT `rimeb` GROWS ANY AT ALL.** It resolves to `climate.temperature=-0.95..-0.45`, and the gate is
#     `most <= -0.45` — it passes by exactly nothing. If the writable path turns out to grow none, the gate
#     wants a hundredth of slack, because "cold enough" should not hinge on a boundary the player cannot see.
#   - **THE `alps` TRAP.** `/age write rimec 4242 age sheer landmass blizzard phenomena frozen climate`
#     resolves to `landmass=alps`, which yields ZERO — it is the landform whose name most says "cold
#     mountains" and the one word a player would reach for. Bug to fix, or a thing to teach?
#   - THE SKATES: 2.26x a walk at terminal speed, no brakes, a ledge a real hazard. Fun, or just fast?

# ══ 8. SKY POLISH ══════════════════════════════════════ OPEN 2026-07-30, DEFERRED BY JONAH ══
# Park these until the main mod has more headway. Neither is a bug; both are "it works, and it should be
# better". Recorded because the leads are fresh.
#
# 8a. THE SPIRE SHOULD BE PERMANENTLY DUSK, WITH ITS STARS ALWAYS OUT.
# It has no sun, so a day/night cycle buys it nothing. Wanted: stars visible at ALL times, light EVEN
# across the cycle at roughly dusk intensity, and time still PROGRESSING so the stars rotate. Today it is
# on the overworld's clock and goes properly dark and properly bright.
# THE LEAD, and the one real unknown: `star_angle` and `star_brightness` come from the SAME timeline
# (`#minecraft:in_overworld`), so rotation and fading cannot be separated by dropping the timeline — that
# would freeze the stars, which is the opposite of what is wanted. Settle first whether a constant
# `EnvironmentAttributeMap` entry on `age_spire.json` OVERRIDES a timeline track or is merely another layer
# under it (`EnvironmentAttributeSystem.bakeLayerSampler`). If it overrides, this is data only: pin
# `star_brightness` and the light attributes and leave `star_angle` to the timeline. If it does not, the
# painter has to stop reading vanilla's `starBrightness` for an Age that says so — which probably means
# `StarField` carrying its own constant brightness and `StarReveal` going away rather than being widened.
#
# 8b. THE WARM/COOL STAR AXIS IS TOO SUBTLE TO SEE.
# `WARM_STAR` (0.95, 0.87, 0.76) and `COOL_STAR` (0.78, 0.85, 1.0) are both nearly white, so the variation
# reads as noise rather than as colour. Push both toward saturation.
# WORTH KNOWING BEFORE TURNING THAT DIAL: the tint is `WARM.lerp(COOL, random.nextFloat())`, and a uniform
# draw puts most stars in the MIDDLE of the axis — neutral — however far apart the ends are. Biasing the
# draw toward the ends will do at least as much as widening it, and probably more.
